Chess3D — three-dimensional chess against an offline engine

Chess3D is a complete game of chess rendered as a three-dimensional set you can orbit, zoom and turn: procedurally generated Staunton pieces on a veneered board, lit like a studio photograph, with a hand-written engine as your opponent. It runs entirely inside this page — no server, no account, no network connection, and nothing to install before the first move.

The set is generated, not downloaded

There is no model file and no texture image anywhere in the project. Every piece is turned from a hand-tuned profile the way a lathe would cut it — foot, plinth, cove, beads, collar — with the knight's head lofted along its own curved spine and the rook's crown built from six tapered merlons. Corners sharper than about thirty degrees are deliberately creased, so a highlight stops at a real arris instead of being averaged away, and every section carries a sub-millimetre ovality so no piece is a perfect solid of revolution.

The board is veneer: the grain is sampled from a different part of the tiling for each of the thirty-two squares, half of them rotated a quarter turn, over a hairline seam. Marble, felt and brass are generated the same way, and the room is a small studio — warm key softbox, cool fill panel, rim strip — captured into an environment map at load time. Sound is synthesised with WebAudio and played through a generated 0.45-second room, which is why a piece landing sounds like wood on a table rather than a beep.

The opponent is a real engine

The computer player is a negamax search with alpha-beta pruning, iterative deepening, a transposition table, quiescence search, check extension and killer/history move ordering. It is written from scratch in JavaScript, with no Stockfish, no WebAssembly and no network call, and it runs in a Web Worker so the board keeps rendering while it thinks. Six difficulty tiers set the depth, the time budget and how often the engine is allowed to settle for a slightly worse move, from a beginner that gives pieces away to a tier that asks for twelve plies within five seconds per move.

Every rule, including the awkward ones

Castling with the right to lose it, en passant, promotion with a choice of four pieces rather than an assumed queen, check, checkmate, stalemate, the fifty-move rule, threefold repetition and insufficient material. Undo takes back your move and the engine's reply; the move list is standard algebraic notation, and clicking a move shows the board as it stood at that point so a game can be reviewed before it is abandoned.

Offline, private, and yours

The game is a static page: no backend, no database, no analytics and no cookies. Your game is auto-saved in the browser and replayed from its moves when you come back, so a reload cannot lose it. A position can be shared as a link — the whole game travels in the URL fragment, which browsers never send to a server — or exported as PGN for any other chess program. A service worker caches the page on the first visit, so it opens with the network switched off and can be installed as an app on a phone or a desktop.

Controls

  • Click or tap a piece, then a destination square, to move it.
  • Drag to orbit the camera; scroll or pinch to zoom.
  • U undo, H hint, N new game, F flip the camera.
  • 1 White view, 2 Black view, 3 side view, 4 top view.
  • Esc leaves the review, the settings sheet or the promotion dialog.

How it is built

Plain ES modules and a vendored copy of Three.js reached through an import map. No build step, no bundler, and no dependency fetched at runtime: the files you downloaded are the files that ran. The rules engine and the search have no rendering dependency at all, which is why they can be unit-tested in Node and reused unchanged inside the Web Worker.
